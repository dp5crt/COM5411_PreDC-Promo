The project started with downloading and installing a pre-existed server, which contained starter configurations and module downloads, this was all done via VMWare. I downloaded the GitHub repoaitory provided and synced it with Git to be able to manually store all changes to the files and automate the evidence produces for each change made, as well as any extra information needed via Git commits. The baseline was in the process of being configured and changes were being made to the StudentConfig and AllNodes files, when I realised a second network adapter was required to set up a public network and a private network. This became a key issue, because I was forced to spend a lot of time trying to add this in from the virtual machine settings but nothing was working. The solution that was found was to export that file for the server and import it into a different virtual machine, VirtualBox. After a while of waiting for this process, the virtual machine was powered on and the second ethernet had finally been found. From there, the second network adapter was configured by making the IPv4Address_Internal    = '192.168.99.10' and the  DnsServers_Internal     = @('127.0.0.1'). The environment for the barmbuzz.local domain then took priority with security coding being vital, with personal information such as: Domain ADministrator and DSRM passwords being protected with code regarding PSCredential objects provided by the orchestrator script. At the beginning stages of the RunBuildMain.ps1, many issues and errors were promptly produced, the DSC compiler recorded most of those issues, suggesting that there were InvalidArgument and ParseError messages. To resolve this I ran the command, Get-DscResource command to investigate the versions of the modules that had been installed and which ones were potentially missing, this showed that the ActiveDirectoryDsc and NetworkingDsc had certain versions that were being used, which needed different property names from the ones that were initally run with. Another error that was reocurring with the StudentConfig file was a Positional Parameter one, the tests had identified that curly brackets inside the node block were incorrectly placed, even though this seems like such an unimportant issue, every minute detail makes a major difference. On top of this, resource blocks such as DnsClient were correctly scoped. The IPAdress code was also providing errors, beacuse the IP adress contained a CIDR notation, which was not how the tests wanted it to be structured, so I solved this by adding a PrefixLength property and provided it with the value of '24'. After finally resolving syntax complications, I moved on to complementing the resource properties with the installed module version by DomainAdministratorCredential to a property that was recognised by VSCode, Credential. The Run_BuildMain.ps1 script was successful, which compiled the MOF file and that allowed for the promotion of this machine to a Domain Controller. Main services including, Active Directory, DNS, and Netlogon changed state from Stopped to Running.
